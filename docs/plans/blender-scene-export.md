## 已实施需求：Blender 工程回读与显示参数往返（2026-11-06）

本节将已确认目标限定为：**重新打开 BandScope 自己导出的 Blender 工程，恢复强度数据、色阶和透明度设置，调整后原位置更新工程。** 与下节多页面扩展共用“工程—条目”元数据和资产契约，不另建任意 `.blend` 导入器。本节为已实施需求与验收依据。

### 打开入口与宿主渲染

- 在独立 Blender 工程对话框提供“打开已有工程”，选择 `.blend` 后校验同名 `.assets/`、`scene.json`、逐条目数组和 VDB；缺失、版本不支持或结构不一致时给出具体错误，不生成空页面。
- 打开后恢复为带工程来源标识的冻结 3D 结果，不伪装成原始实验数据，不恢复时间轴或导出前的完整处理链。多页面工程按唯一条目 ID 恢复各数据体，用户选择条目分别调整；条目身份与来源页面标识仅用于工程管理，不要求原 NPZ 或原页面仍存在。
- 从条目强度数组及显示参数重建 `PublicationSnapshot` 或等价的冻结数据契约，复用现有颜色／透明度计算和 **PyVista/VTK** 体渲染管线。宿主不嵌入 Blender/Cycles，不直接显示 Blender 材质节点。
- 从保存的显示域、相机和画幅信息逆变换回宿主相机；ROI、物理坐标、降序坐标及 E 轴翻转语义保持原样。Cycles 与 VTK 的体积分差异仍需在界面和说明中保留，不承诺逐像素一致。
- 可调整 colormap、黑点、gamma、白点、锁定范围及不透明度映射；保存操作命名为“更新工程”，与原位置及当前条目状态明确关联。已经在 Blender 中打开的工程需重新载入 VDB或重开，界面应提示这一要求。

### 唯一配置与逐条目数据契约

- 不新增与现有配置重复的并列文件。升级工程 schema，扩展同名 `.assets/scene.json` 作为**唯一权威编辑配置**；`.blend` 内已有 `scene_metadata` 等内嵌副本只供生成期诊断，不作为回读依据，更新资产时也不要求改写它。
- `scene.json` 按工程及条目记录资产路径、来源、坐标、相机和 `bandscope_edit` 编辑状态。编辑状态至少包含 `cmap_name`、`levels_params`、`locked_range`、`include_zero`、`opacity_mode`、格式版本、可编辑能力及已烘焙效果标记；多页面扩展的布局和预设信息与科学显示状态分层保存。
- `arrays.npz` 继续保存处理后强度及用于复核的显示颜色、alpha、密度数组；重新调色以强度数组和编辑参数为准，不从最终 RGB 或 Blender 材质反推科学强度。`volume.vdb` 继续作为 Blender 的实际渲染资产。
- 冻结结果使用自身保存的有效锁定范围，不回写或改变当前数据源的色阶锁定作用域。多页面读取、编辑和转换逐条目进行，避免同时持有全部页面的颜色及密度中间数组。
- 新格式导出在首次生成时即写全上述编辑状态，避免导出后再猜测参数。回读与下节多页面工程级请求、唯一条目 ID 和独立资产目录同步设计，避免为单页和多页建立两套不兼容格式。

### 编辑范围与旧格式边界

- 第一版保证普通全局色阶、colormap 和不透明度的基础往返。局部增强、插件透明度倍率及其他已解析到体素的效果不宣称可以拆分编辑；新导出须记录可识别的烘焙效果，调整会改变或丢弃这些效果时必须在覆盖保存前明确警告，不静默声称完整恢复。
- schema 6 及更早工程只做有限恢复：可读取强度、坐标和已有色阶换算信息，缺失的 colormap 由用户重新选择；无法判断是否含局部增强或插件效果时显示通用烘焙警告，不声称无损还原。旧格式恢复路径不得改变新格式的权威配置规则。
- 完整局部增强规则、插件参数、原始处理链和时间轴恢复留作后续扩展，不阻塞本轮基础显示参数往返。
- 仅支持 BandScope 导出且配套资产完整的工程。普通 `.blend`、被移到其他位置而未携带资产的工程，或已改为不受支持体积结构的工程，不作为通用体数据导入。

### 原位更新与 Blender 场景保护

- 原位更新只替换修改条目的 VDB、对应 `arrays.npz` 和工程级 `scene.json`；**不重建、不保存、不改写 `.blend`**。因此用户后来在 Blender 中修改的相机、灯光、排版、附加对象和材质创作均保留，科学体仍通过原相对路径读取更新后的 VDB。
- 保存前通过现有外部 Blender 后台脚本以只读方式打开工程，核对条目、体对象及相对 VDB 路径仍指向预期资产；只增加 OpenVDB 写出和工程检查模式，不把 `bpy` 或 OpenVDB 加入 BandScope 宿主运行依赖。
- 所有修改文件先在同目录暂存并校验，再备份、整体提交；任一条目或配置写入失败均回滚到更新前状态。提交前复查来源 `.blend`、资产和配置的大小、时间戳或摘要，发现并发变化则中止，不能覆盖外部程序刚写入的内容。
- `.blend` 中的体对象被删除、VDB 路径改向、资产被其他程序改动或文件无法替换时，更新必须失败并保留旧工程。不能为了完成更新而重建整个场景或静默另存一份。
- 本流程只适用于“打开已有工程后调整显示参数”；从活动页面重新导出仍沿用既有覆盖确认。显示参数更新不重排数据组，不重建坐标轴、方向标、辅助盒框或长方体预设，也不改变其布局、可见性和用户后续编辑。

### 实施顺序与验收

1. **统一工程契约与读取器。** 和下节多页面格式共同确定工程、条目及 `bandscope_edit` 元数据，完成新格式写出、回读、旧格式有限恢复和严格错误校验。合成测试覆盖 colormap、三点色阶、gamma、锁定范围、各透明度模式、NaN／Inf、非立方体、ROI、降序坐标和相机逆变换。
2. **接入冻结结果与 PyVista 编辑。** 验证打开后的颜色、alpha 与重新计算结果一致，多页面逐条目不串状态，工程来源切换不影响当前数据源；局部增强及插件烘焙效果具有准确标记和保存警告。
3. **实现只更新资产的保存链路。** 复用现有密度换算、Blender 后台 OpenVDB 能力和事务提交，自动化覆盖缺失资产、任意 `.blend`、路径改向、并发变化、部分写入失败及完整回滚；保存前后 `.blend` 字节摘要保持不变。
4. **完成真实 Blender 往返验收。** 导出后调整色阶与不透明度并原位更新，重开确认 VDB 和 Cycles 渲染反映新参数；预先加入的相机、灯光、文字和附加对象保持存在。覆盖单页、多页、六项预设、目录搬移、旧格式提示及 Blender 已打开时的重载说明。
5. **完成回归与交付记录。** 运行受影响测试及 `python -m unittest discover -s tests -t . -v`，使用 `.local/data/WSe2_step.npz` 做真实数据和窗口验收，并复验 CPU／NVIDIA 冻结包的读取器、独立脚本资源及外部进程链路。更新使用说明，将自动化、真实渲染、人工视觉和冻结包结果分别写回本主记录；本轮不包含发布。

## 目标与首版范围

在现有导出面板增加 **“Blender 工程（需要本机安装 Blender）”**，将当前冻结的 3D 视图转换为可继续创作的 Blender 工程，保留数据体、颜色与透明度、相机投影和坐标参考。

首版每次导出一个视图或时间帧；多个结果通过 Blender 的 Append 功能组合。提供独立的数据 Collection 和父对象，便于整体移动、旋转、缩放。辅助平面由用户在 Blender 中添加。

首版不包含 SolidWorks／等值面导出、时间序列动画、应用内多视图排版，也不把截图中的二维色条、文字排版和主体缩放设置转换成三维对象。

## 界面与交付形式

- 在导出面板增加“导出类型”：图片、**Blender 工程（需要本机安装 Blender）**。默认仍为图片；仅 3D 快照提供 Blender 选项，不将 `.blend` 混入图片格式枚举。

## 实现与数据契约

### 宿主与 Blender 分离

- 业务集中于 `bandscope/exporting/`，复用 `PublicationSnapshot`，不新增插件 API。
- 增加纯数据接口 `prepare_blender_scene(snapshot) → BlenderSceneData`，输出数组、坐标映射、相机和显示参数；后台任务不得读取窗口控件或活动 VTK 对象。
- BandScope 准备临时数组和版本化场景描述；调用 Blender 后台运行随程序提供的独立脚本，完成 VDB、材质、对象和 `.blend` 生成。
- 本机已确认 Blender **5.2.3 LTS** 的 OpenVDB、NumPy 和体积系数节点可用，以此作为首版验收基线。启动前检查必要能力，缺失时给出明确错误。OpenVDB 使用 Blender 自带模块，不加入 BandScope 的运行依赖。[Blender 模块说明](https://developer.blender.org/docs/release_notes/4.4/python_api/)

### 坐标与相机

- 保留完整数据域、ROI 绝对起点、显示比例、物理坐标数组及单位；统一将当前 0–200 显示空间映射为居中的 2 个 Blender 单位，并同步转换相机、裁剪距离和透明度单位距离。
- E、kx、ky 保留科学坐标含义，不解释为毫米。坐标参考采用可编辑的三轴箭头、轴名和范围标记。
- 无论主视图的「坐标轴」开关是否开启，都在 `Orientation marker · publication` 子 Collection 生成默认可见的图片同款三轴方向标：复用图片导出的相机轴角色、投影向量、统一缩放和标签布局，使用单色曲线箭头杆、三角面箭头及 `kx / ky / E` 短标签；下标为独立 Text 对象。方向标位于相机画面左下角，保留纵深缩短，精确正视纵深轴时用圆环和实心点；所有对象挂在 `BandScope Root` 下，不使用贴图。
- 无论主视图的「坐标轴」开关是否开启，都生成把数据体框住的辅助盒框：取坐标轴框与数据体（含额外裁剪）的并集再向外扩 0.1 个 Blender 单位（标准域为固定的 `±1.1`），每一面都严格大于坐标轴框；盒框放在 `Guide frame · auxiliary` 子 Collection，供用户对齐辅助平面、文字和相机，默认不参与渲染。
- 3D 的 E 轴翻转已由相机表达，禁止再次翻转数组或 ROI。
- 恢复相机位置、焦点、up、正交／透视和画幅比例。采用垂直 sensor fit；正交高度为换算后的 `2 × parallel_scale`，透视焦距由垂直视角计算。
- 默认渲染长边 1920 像素，保持冻结视口比例和方形像素；在 Blender 中可以继续修改。

### 体数据与材质

- 复用现有颜色／透明度计算，包含色阶锁定、gamma、局部增强和插件透明度倍率；所有效果只应用一次。
- 保存当前处理后强度、显示颜色和体密度网格。首版提供材质节点中的颜色调整及密度倍率，不在 Blender 内重建 BandScope 的完整处理面板。
- 用 `σ = -log(1-α) / 单位距离` 转换体密度，对 α 接近 1 做有限截断；使用无散射的吸收＋发射材质，发射系数为 `σ × color`，避免默认烟雾光照改变科学配色。[体积系数节点说明](https://docs.blender.org/manual/ru/5.2/render/shader_nodes/shader/volume_coefficients.html)
- NaN／Inf 和裁空位置透明；精确应用数据边界及额外裁剪范围，处理 VDB 边缘半体素扩展。关闭弱信号裁除阈值，设置对象空间密度，使整体缩放保持透明度观感。
- 使用明确的颜色空间转换和 Standard 显示设置；默认透明背景。空间关系要求可验证，外观允许经过校准的渲染器差异，不承诺像素级一致。

### 工程组织与失败处理

- 数据体和坐标参考置于同一 Collection、同一父 Empty 下；相机放在独立 Collection。追加数据 Collection 不替换目标场景相机。
- 追加后的工程可以引用原资产目录；使用说明明确保留这些目录，另存工程不会自动复制 VDB。
- 后台启动使用参数列表、隐藏窗口和工厂配置，不加载用户启动文件。数组准备及外部转换不阻塞 GUI。
- 全部产物先暂存并校验，成功后整体提交；覆盖时确认工程和配套资产范围。取消、转换失败或磁盘错误均保留原文件，仅清理本次临时产物。
