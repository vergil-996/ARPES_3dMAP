## 目标与硬件开销

每次成功加载 `.npz`、经转换的 `.mat` 或受支持的 `.bsview.json` 都新增独立工作区，保留此前数据及分析；顶部下拉框切换数据源，左侧仅显示当前数据的视图树。

现有入口已通过 `load_data()` 分流 `.bsview.json`，由 `ViewRecipeDocument` 校验并通过 `RecipeEvaluator` 预检，再恢复工作区。目前 JSON 导入仍提示替换当前分析；本计划将其改为新增会话，不覆盖其他已打开的数据。支持对象是现行 `bandscope.view` 格式的视图复现文件，不扩展为任意 `.json` 数据导入。

主要开销是内存。以项目默认的 `150×150×200×25` 数据为例，当前加载器统一转为 `float32`，每份原始数组约 **429 MiB**，5 份约 **2.10 GiB**；完整去噪结果可能再占同等空间。规划时本机约有 **23.6 GiB 物理内存**，少量数据共存通常可控，实际容量仍取决于处理结果、临时数组和其他程序。共用渲染器后，CPU、显卡持续负荷不会简单随数据份数倍增。

以上是数组大小计算及源码分析，不是性能实测结论。加载峰值、切换耗时和实际显存占用须在实现后验证。

复现 JSON 本身不嵌入主原始数据，加载时仍需读取它引用的 NPZ，并可能执行去噪及派生计算。因此每次打开复现文件也有对应原始数组、恢复结果和预检临时内存开销，不能仅按 JSON 文件大小估算。

## 已确认的交互行为

- 在顶部“加载数据”按钮后增加 SiliconUI 可编辑下拉框，默认显示文件名去除扩展名；复现文件去掉完整的 `.bsview.json` 后缀。提示信息区分入口文件路径和实际主 NPZ 路径。编辑仅修改数据源别名，原始视图名称和导出默认名保持独立；Enter 或失焦提交，Esc 撤销，空名称恢复原值，重名自动追加序号。
- 数据源数量从 1 变为 2 时，以现有 **220 ms 宽度展开＋淡入**显示；从 2 变为 1 时反向收起；0 或 1 份时不占布局空间。快速连续操作时从当前动画位置衔接。
- 原始数据加载成功后选中新数据的原始视图；复现文件加载成功后新增一个选项，恢复来源分支并选中其保存的目标页面，同时恢复显示、相机和出版草稿。复现文件中的额外曲线来源记录不单独生成下拉选项。
- 切回已有数据时恢复上次页面、帧、参数和相机。重复加载同一 NPZ、同一复现 JSON，或引用同一 NPZ 的不同复现 JSON，均新增独立分析，不覆盖、合并已有会话。
- 删除左侧原始视图即关闭整份数据，包括全部派生页和关联任务。关闭后选择列表中的前一份，没有前一份则选择后一份；最后一份关闭后回到未加载界面。
- 采用内存保留策略，切源不卸载原始数组；不设置固定数据源数量上限。

## 实现方案与内部接口

### 会话模型与共享界面

- 新增 `SourceSession` 和管理器，提供新增已准备数据、激活、关闭及页面归属查询。每源保存稳定 UUID、入口类型与路径、实际主 NPZ 路径、别名、只读原始数组、坐标元信息、处理版本、页面树与导航状态，以及裁剪、增强、插件和出版状态。页面 ID 全局唯一，数据域和缓存身份包含所属源。
- 会话 UUID 与现有 `SourceIdentity`、配方来源 ID 分开：前者标识独立工作区，后者继续标识数据内容、布局及计算来源。同一 NPZ 的多个会话不能因摘要相同而合并。保存各源的 `source_identity`、`source_layout`、来源记录、恢复结果及目标视图状态，切源不得清空或读写其他源的复现记录。
- 数据域/ROI ID 保持会话内局部标识，保留完整数据域的 `full` 语义；跨源注册、缓存及任务归属使用 `(session_uuid, scope_id)` 组合键，不将 `full` 改为新 UUID。
- 保留一套主窗口、工作区控件、VTK/Matplotlib 画布、计算后端和插件实例；不为每份数据创建主窗口或渲染器。窗口中的活动数据字段只指向当前会话，原始数组的多个别名继续共享缓冲区。
- 切源先提交当前编辑并保存旧源页面、插件、相机和导航状态，失效显示任务、清理交互对象，再绑定目标会话并阻断信号恢复控件，最后只触发一次页面激活和刷新。搜索、展开、顺序和滚动位置随源保存，栏宽保持全局。

### 加载与关闭事务

- 原始数据使用临时加载器准备，成功后才登记；失败或取消完整保留现有会话。原始数据新增源初始化独立的原始视图和默认状态，不再调用会清空全部旧分析的加载重置流程。
- 复现 JSON 复用现有格式/版本、相对路径、重新定位、SHA-256、轴布局、科学参数和结果快照校验，以及插件匹配时重算、不匹配时快照恢复的规则。将预检与“应用到新会话”分开；全部准备成功后才登记并切换，不再提示替换已有分析。预检、重新定位取消或提交失败时，不留下半成品选项，也不改变已有源和后台任务。
- 导入 JSON 后为运行时页面建立新的全局唯一 ID，同步映射父子关系、原始页/目标页及按页保存的视图、结果、轴标题和出版状态；ROI 标识按会话隔离。先校验原文档，再建立运行时映射，不直接篡改已校验文档的内容摘要与不可变配方 ID；后续导出通过现有配方捕获和校验流程生成一致的新文档。
- 根视图删除走独立的源级关闭事务，避免逐页删除期间误激活其他页面；包含隐藏后代和固定工具页。先标记源关闭并摘除页面记录，再执行清理，最后统一切换存活源或空界面。
- 关闭时清理所属页面、裁剪、轴标题、出版草稿、缓存及当前显示引用，只取消该源的任务；不依赖 `page_closed(home)` 回调中途切源。

### 异步任务、插件与出版状态

- 刷新、去噪和缓存均绑定源身份及处理代次。切源使显示预览、未完成去噪失效，保留配置，切回按需重算。重算完成前禁止导出未就绪结果，不能把未处理原始数据当作已处理结果。
- 明确提交的插件分析继续执行。宿主内部记录快照和任务的源归属，完成后核对所属源、页面和处理代次，再向原会话登记结果，不抢焦点；来源关闭或版本过期则丢弃。保留现有全应用分析队列限额，公开插件 API 保持兼容。
- 拆开插件“面板状态重置”和“取消全部分析”的现有耦合。插件切源先保存旧状态，清旧临时状态再恢复目标参数；缺少保存记录的新源必须使用默认状态，避免继承旧源峰位等设置。
- 曲线和色带剪贴板继续全局共享，曲线维持现有类型与横轴匹配校验。已打开的出版预览绑定原来源快照，切源后仍写回原页面；来源关闭时作废对应预览。
- 保持现有图片与 `.bsview.json` 配对导出、冻结预览和写入失败回滚行为；原始数据身份、来源闭包、恢复的插件效果和出版草稿都取自预览所属会话。跨源曲线复制保留其不可变来源闭包，关闭原会话后仍能粘贴快照及导出完整来源，不能只留下无法解析的 `recipe_id`。

### 资源管理

- 每源只保留一份原始缓冲区；可重建 CPU 缓存统一采用现有预算 `min(4 GiB, 物理内存×20%)`，避免逐源倍增。覆盖可重建的去噪、ROI、旋转、积分和导数缓存；非活动会话不额外强引用已淘汰缓存。
- 原始数组、必要的不可重建结果快照、当前工作缓冲区和运行中任务的临时数组不属于缓存预算，因此该预算不是进程总内存上限。
- GPU 仅保留当前显示所需资源。关闭源时驱逐其缓存并释放关联数组视图；运行中的任务采用现有协作取消或结果失效机制，可能延迟到任务结束才释放内存。
