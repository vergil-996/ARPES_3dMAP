# BandScope 平带高斯不透明度插件：第一版实施计划

日期：2026-09-27。当前状态：已有实现与自动化测试，实测数据视觉验收仍待确认。

目录整理说明：原方案基于 v1.7.0 工作区，现有工作区已包含 v1.8.0 的插件框架与平带源码。正文保留设计背景；新位置以 [模块地图](../architecture/repository-map.md) 为准，运行命令见 [插件指南](../development/plugins.md)。不能将代码存在等同于原计划全部验收完成。第一版支持用户自定平带数量与能量，不固定三条。

## 1. 目标与交付范围

为出图提供一个独立安装的官方扩展：用户自行添加需要突出的平带、设定每条的能量位置，分别调整覆盖厚度和增强程度，同时淡化远离目标能量的背景。平带数量由用户决定，不预设固定条数。主程序与插件在同一 GitHub 仓库开发，在同一个 Release 中分别提供基础安装包和插件包。

第一版只覆盖 3D 体渲染和现有 3D 图片导出。能量中心由用户输入，宽度看图手动调整；无需自动找峰、洛伦兹拟合或 MRF 重构。插件只改变显示用不透明度，不改变原始强度数组、颜色映射、色条、分析结果或数据导出的数值。

基础安装包只包含通用扩展接口、扩展管理入口和渲染支持，不包含平带插件代码。第一版采用本地导入扩展包、安装或卸载后重启生效。插件使用已有 Python/NumPy/Qt 运行环境，不安装新的计算依赖。

## 2. 用户操作

1. 从项目 Release 下载与当前主程序匹配的“平带增强”扩展包。
2. 在“扩展管理”中导入，校验通过后安装并提示重启。
3. 加载数据、切换到 3D 视图，在“渲染控制”中打开插件提供的“平带增强”卡片。
4. 点击“添加平带”增加所需条目，自行输入每条的能量中心；条目可删除，每条带可独立启用、调节厚度和增强量。
5. 先调背景保留比例，再调宽度，最后单独提高弱带的增强量。
6. 使用现有图片导出入口生成图片；导出沿用当前效果。

控件约定：

| 控件 | 行为 |
|---|---|
| 效果总开关 | 随时与原图比较；关闭时绕过插件效果，恢复原有渲染 |
| 添加平带 | 增加一条独立参数行，用户通过添加/删除决定数量 |
| 可增删参数列表 | 每条包含启用、能量中心、厚度、增强量和删除按钮；条目较多时支持滚动 |
| 能量中心 | 每条均可自由输入和修改实际能量坐标；不编造默认峰位，填写有效值后才启用对应行 |
| 厚度 | 用高斯半高全宽 FWHM 表示，比标准差更直观；与中心使用相同坐标单位 |
| 增强量 | 对高斯中心额外增加的不透明度倍率，各条独立调节 |
| 背景保留 | 0%–100%；100% 表示远离目标的区域保持原有透明度 |
| 重置显示参数 | 恢复背景、增强量和宽度的建议值，保留用户选定的数量与峰位 |

建议起始设置：背景保留 20%，各条额外增强量 0.8。对于分离良好的峰，其中心倍率为 0.2 + 0.8 = 1，主要通过压低背景突出能带；弱带可继续提高增强量。厚度初值根据能量采样间距给出可修改建议，不把它当作测量得到的线宽。第一版增强量范围先设为 0–5，视觉验收时检查是否需要调整。

首次打开列表为空，显示“添加平带”入口；新增条目的能量留空，填写有效参数后可启用。删除条目后立即移除其效果，不影响其他条目的设置。列表为空或全部停用时保持原图，并提示添加或启用平带。启用行必须具有有限的中心、正的宽度和非负增强量；无效编辑保留上一次有效预览，不能使 Qt 槽异常退出。峰位不在当前 ROI 能量范围内时提示，但保留参数以便返回完整数据。

坐标有可信单位时显示该单位；只有索引时显示 index；有坐标但缺少单位元数据时显示“坐标值”，不自动标成 eV。切换到 1D/2D 时卡片不参与渲染，返回 3D 时恢复状态。

## 3. 透明度模型

设用户添加 N 条能带，S 为其中已启用且参数有效的条目集合。对每条 i ∈ S，设中心为 E_i、半高全宽为 w_i、增强量为 a_i：

```text
G_i(E) = exp[-4 ln(2) ((E - E_i) / w_i)^2]
m(E)   = b + max_{i in S}[a_i G_i(E)]
alpha  = clip(alpha_base * m(E), 0, 1)
```

其中 b 是背景保留比例，alpha_base 是现有色阶与透明度映射产生的基础不透明度。当 S 为空时直接返回 alpha_base，不计算空集合最大值，也不单独淡化整幅背景。

- 高斯在中心为 1，在 E_i ± w_i/2 处为 0.5。
- 离开所有选定能量区域后，倍率趋近 b，实现背景淡化。
- 使用最大值合并，避免重叠高斯简单相加导致交叠区域异常增厚。
- 原本透明的体素仍透明；NaN/Inf 和裁剪遮罩继续强制不可见。
- 增强只作用于不透明度，不用修改强度值来间接改变颜色。
- 显示控制是高斯形的倍率；由于基础不透明度还取决于实验强度，最终体素不透明度不要求严格呈高斯线形。

首版 UI、参数保存、预设、页面继承与导出均使用可变长度列表，每条具有稳定 ID，增加或删除条目不会串用其他条目的参数。高斯算法及其参数含义全部属于插件，主程序只消费通用的非负透明度倍率。计算时逐条更新最大值向量，避免因条目增加而同时保存所有高斯向量，更不为每条平带创建一个三维数组。

目录整理后 `tests/` 已解除 Git 忽略，宿主与插件测试统一运行：`python -m unittest discover -s tests -t . -v`。普通提交、PR 和 release 工作流均执行该回归套件，编译检查单独保留。

宿主第一版提供四类能力：

1. **上下文**：当前视图、E 坐标与单位、ROI/绝对数据范围、时间帧和显示方向。输入只读；本插件计算权重只需能量轴，无需复制整块强度数据。
2. **面板注册**：插件返回参数面板，宿主负责挂载、显隐和生命周期。插件不直接访问 `My3DAnalyzer` 的私有字段或操纵 VTK。
3. **效果提交**：插件输出一个与当前能量轴对应的一维倍率向量；宿主负责校验、广播并应用。为未来空间权重保留协议扩展位置，首版无需实现 MRF 或任意自定义渲染器。
4. **状态与刷新**：宿主按页面保存插件 ID、参数 schema 版本和参数，插件请求显示刷新；主程序处理节流、失效和导出快照。

第一版按页面保存效果状态，裁剪派生页继承一份独立参数副本，页面之间不会互相覆盖。时间帧变化时沿用用户设定的能量窗口；加载新的数据文件时重置效果，不把旧数据的峰位自动套用到新数据。

此处“保存”指现有页面状态和额外提供的插件参数预设 JSON 导入/导出，不扩展成整个工作区的跨重启项目保存系统。预设包含完整条目列表、每条的 ID/启用状态/参数和单位信息；导入后恢复实际条目数量，检查单位及当前能量范围，不作隐含单位换算。

## 5. 渲染与图片导出接入

当前 `VolumeRenderSession` 使用按强度的一维传递函数，同样强度的体素不能因所在能量不同而采用不同透明度。因此，安装加载代码以外，还必须增加宿主的空间透明度能力。

优先验证 VTK 双分量体数据方案：第一个分量保留强度以映射颜色，第二个分量表达独立不透明度，使用 dependent components。PyVista 文档明确描述双分量数据可分别进入颜色和透明度传递函数，但当前项目中的复用缓冲区、mapper、裁剪 mask 和导出仍需实测。

参考：[PyVista VolumeProperty.independent_components](https://docs.pyvista.org/api/plotting/_autosummary/pyvista.plotting.volume_property.volumeproperty.independent_components)。

先做有门槛的渲染验证，再决定正式实现：必须同时通过颜色保持、缺失体素遮罩、拖动裁剪、场景复用和离屏导出检查。如双分量方案在当前 VTK 路径存在兼容问题，再评估显式 RGBA 等实现；不能以改写原始强度数组代替。

关键约定：

- 主视图与导出共用同一份倍率应用逻辑。快照冻结已解析的能量轴、倍率和参数，离屏渲染不再读取实时控件。
- 插件峰位按照当前显示的 E 坐标解释。宿主复用既有 E 轴翻转语义，将权重对应到正确体素；插件不额外翻转数据。
- 对 compact ROI 使用绝对范围截取能量轴；预览降采样时数据与能量权重使用相同索引。权重不因 ROI 的缩小而重新拉伸。
- 旋转相机不重算权重；Z 轴数据旋转仍复用现有处理路径。能量坐标、参数或数据帧相关缓存失效时才更新必要部分。
- 保留已有 NaN/Inf mask 和裁剪掩膜，低背景比例不会使隐藏区域重新出现。
- 只缓存一维倍率；宿主在必要时生成独立 alpha 通道，记录额外缓冲区内存，不让插件反复分配三维权重。
- 插件关闭时使用原有渲染路径；缺失、不兼容或加载失败的插件不执行，页面可以正常打开，并明确提示其效果未应用。

## 6. 安装、版本与发布

扩展包使用 ZIP 容器和专用文件扩展名，例如 `.bsplugin`。包含清单、Python 代码及必要的 UI 资源；不带自己的 NumPy、Qt、VTK 或 CUDA。CPU 与 NVIDIA 安装版共用同一个插件包。

清单至少包含：`id`、`name`、`version`、`api_version`、`requires_app`、`entry_point`、`capabilities`。第一版 `api_version = 1`，`requires_app` 精确匹配发布时的主程序版本，允许后续扩大已验证的版本范围。

安装根目录固定为 `%LOCALAPPDATA%\BandScope\extensions`，与基础软件安装目录分离。现有安装器升级会清理 `{app}\_internal`，并递归收集构建产物，因此插件不能存放在 `_internal` 或随 dist 混入基础包。

运行时只从用户扩展安装目录加载明确安装并启用的扩展；源码目录不会自动被当作已安装插件。使用插件专属模块名、明确入口和包内相对导入，不把整个扩展目录添加到全局模块搜索路径。Qt 应用及宿主接口就绪后才加载入口。开发版也通过同一个构建/安装流程验收，避免出现“源码可用、安装版缺依赖”。

安装流程：读取清单和检查兼容性 → 校验包结构、大小和路径 → 解包到用户目录内的临时目录 → 完整校验 → 提交安装 → 重启生效。新版本写入独立版本目录，注册表记录下次启动选用的版本，避免覆盖 Windows 上仍在使用的文件。失败保留原有已安装版本。不能在检查兼容性前导入插件代码。

卸载流程：记录卸载请求 → 提示重启 → 下次启动加载插件前移除该插件目录。删除目标必须根据插件 ID 在固定安装根下解析，不能由包任意指定。包内绝对路径、路径穿越和链接等不合规范条目应拒绝。

发布产物：基础 CPU 安装包、基础 NVIDIA 安装包、平带插件包及相应 SHA-256 文件。同一个仓库、同一个应用 Release，由 CI 打包一次插件供两种基础安装包使用。当前 CI 只上传 `.exe` 和 `.sha256`，需增加通用插件 artifact，并让 Release job 等待并收集该产物。扩展不单独创建会干扰主程序更新检测的应用版本 tag。新增功能的发布版本在实施时确定，本计划中的 1.7.0 仅表示检查时版本。

必须检查 PyInstaller 的两个 spec 与安装器：插件源码不能被静态 import、hiddenimports 或整目录复制带进基础安装包；宿主接口及插件实际使用的共享依赖必须存在于安装版。使用源码之外的干净安装目录验证。

第一版插件升级仍用手动导入匹配的新包；主程序升级后，不兼容插件保留在磁盘但停止加载，界面说明需要安装兼容版本。现有主程序更新流程继续只选择 CPU/NVIDIA 安装器，不把扩展资产识别成应用更新。

## 7. 实施顺序与阶段交付

| 阶段 | 工作 | 阶段完成标准 |
|---|---|---|
| A：验证渲染通道 | 用小型合成多平带数据验证独立透明度、背景淡化、NaN/裁剪 mask 和导出 | 同强度不同能量可有不同 alpha，颜色/色条保持正确，缺失区域不可见 |
| B：最小宿主机制 | 建立版本化协议、注册器、本地安装管理、加载与页面状态连接；尽早在真实 PyInstaller 产物中验证动态导入 | 未安装插件的主程序正常；匹配包在源码和冻结版本均可注册面板；不兼容包不执行 |
| C：平带插件 | 可增删条目列表、独立能量中心/FWHM/增强量、背景比例、即时预览及参数预设 | 数量与能量由用户选定，可以单独突出弱带，删除/停用/重置行为明确 |
| D：完整集成 | 对齐能量坐标、ROI、E 翻转、降采样、时间帧、裁剪继承和导出 | 效果定位正确，页面状态独立，屏幕和图片采用同一效果 |
| E：独立分发 | 扩展构建脚本、CI 资产、干净安装/卸载、使用说明 | 基础包无插件，CPU/GPU 安装版可分别安装同一插件并完成出图 |

阶段 A 的验证是首要技术依赖，应先于完整的安装管理界面开发。发布前至少取得一组真实平带数据进行视觉验收；用户的具体能量值在使用阶段填写，不阻塞接口与合成数据验证。

## 8. 验收清单

### 数学和数据

- 覆盖 0、1、3、8 条及更多条目的情况；各条中心/宽度/增强量独立生效，高斯半高位置与 FWHM 定义一致。
- 增删条目、修改能量、重复中心和重叠窗口有确定行为；相同中心不因重复条目而叠加增强，仍采用最大值。
- 远离目标处倍率趋近背景比例，重叠处采用最大值而非相加。
- alpha 始终有限且在 [0, 1]；原始数组逐位保持一致，导出的科学数据数值不受影响。
- 零增强、背景为 0 或 1、单条启用、全部停用、无效参数和空 ROI 都有确定行为。

### 渲染和状态

- 同强度不同能量的体素具有相同颜色、不同透明度；色阶锁定仍有效。
- 升序和降序 E 坐标、E 翻转、非零起点 ROI、连续裁剪与预览降采样均定位正确。
- NaN/Inf 和裁剪排除区域保持透明；裁剪交互淡化结束后恢复插件效果。
- 页面切换、帧切换、相机旋转和数据旋转不串用旧权重；新文件不继承旧峰位。
- 删除中间或最后一条后不残留旧效果；页面继承与预设往返恢复实际条目数量、启用状态和参数；较多条目时列表可正常滚动和编辑。
- 原图/增强图可以切换；提高某条弱带增强量不会额外叠加其他带的高斯峰。
- 3D 截图样式、预览与正式 PNG 导出共用同一 alpha 语义；允许画布背景和排版差异，不把视觉背景差异误判为效果丢失。

### 安装和分发

- 在没有源码目录的干净环境中，基础安装包不会出现或加载平带插件。
- 导入有效包、重复安装、覆盖更新、损坏包、版本不兼容、加载异常、卸载后重启均检查。
- 包校验/解包失败不破坏已安装版本；安装路径不能越出用户扩展根目录。
- 主程序升级后能识别扩展兼容状态；应用更新检测仍正确选择基础安装器。
- 新增验收测试实际进入 Git 和 CI；基础包构建清单确认不包含插件源文件。

## 附录：实施记录（2026-09-27）

本文档正文为计划，未作修改。以下是实施阶段落地时与计划不同的关键点，供后续维护参考。

### 渲染通道的实测结论

计划 §5 优先验证的 VTK 双分量方案成立，但落地方式与原文措辞不同：

- 必须使用**二分量 + `IndependentComponents(False)`**（依赖分量 L-A 语义），而不是原文写的
  “使用 dependent components”之后又引用 independent_components 的矛盾表述。本机 VTK 9.6 的
  `IndependentComponents` 默认为 On，单分量体数据必须保持 On。
- `pyvista.Plotter.add_volume` 拒绝二分量标量，宿主用“先按单分量 `add_volume` 建好标量条与
  传递函数，再把 `mapper.dataset` 指向二分量网格”的方式接入；关闭效果时反向切回。
- 二分量模式下 `prop.SetScalarOpacity` 必须放在 `lookup_table.apply_cmap()` **之后**，
  否则会被查色表重建的不透明度折线覆盖。

### 已知差异（未能在参数层面消除）

同一 alpha 下，二分量路径与单分量路径的成像不是逐位相同。实测定位到原因是
**二分量路径不做 `ScalarOpacityUnitDistance` 修正，单分量路径做**；把两侧的该值设成相同
仍有残余差异，说明还有采样层面的差别。表现为开启效果后画面整体偏实心（实测平均亮度差
在 20% 以内，集中在强度梯度大的位置）。

处理方式：接受该差异并在插件 README 与主 README 的「已知限制」里写明；验收测试改为断言
「关闭效果逐位还原」「两条路径结构一致（相关系数）」而不是「亮度一致」。
`scripts/verify_flat_band_alpha.py` 会把该偏差作为参考值打印出来。

### 其他落地细节

- 宿主对外提供的一维倍率定义在**完整**能量轴上；翻转与紧凑 ROI 由宿主用
  `plugin_api.align_multiplier_to_voxels` 对齐到体素，插件不翻转数据、不感知 ROI。
- alpha 通道缓冲区为 `(N, 2) float32`，比单分量多 4 字节/体素；这是本功能唯一按体素规模
  增长的缓冲区，已记入 `render_core.VolumeAlphaChannel` 的文档注释。
- 主程序版本提升到 1.8.0，插件清单 `requires_app` 与之一致；`scripts/release/build_plugin.py`
  会在两者不一致时直接构建失败，两个 PyInstaller spec 也会在扩展源码混进基础包时失败。
- CI 的 `test` job 由只跑 `compileall` 改为真实执行统一的 `tests/`；新增 `plugin` job
  单独打包扩展，`release` job 等待并一并发布。
