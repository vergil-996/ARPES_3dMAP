# Blender 工程导出第二模式：柔和受光

日期：2026-11-12。状态：功能实现、自动化、真实 Blender、真实窗口及开发冻结包验收已完成；已随 v1.20.0 发布（2026-11-13，GitHub 与 MatElab），保留维护者人工视觉复核。本文是本事项唯一状态主记录。

负责范围：`bandscope/exporting/` 的导出界面、工程契约、材质与灯光，以及对应的 `tests/exporting/`、`scripts/validation/` 和导出说明。已接入 `emission`／`hybrid_lit`、schema 11、逐条目三灯灯组和更新兼容；实施者已抽查图像，灰白合成体高光截断需维护者重点复核，不能把生成成功等同于质感获认可。

## 1. 目标与交互

新增“散射为主＋少量自发光”的数据体模式，用灯光增强空间层次，同时保留内部结构的可见性。

- 导出窗口增加“数据体外观”下拉框，应用于全部选中页面：
  - **自发光**：`emission`，保持现有行为，仍为默认选项。
  - **柔和受光**：`hybrid_lit`，自动生成混合材质和配套灯光。
- 按用户已确认的选择，导出窗口只提供模式选择；材质参数和灯光在 Blender 内调整。首期不增加跨重启的选项记忆。
- 模式在提交导出请求时冻结，任务期间禁用选择。五项辅助预设继续独立工作，全部关闭时仍生成第二模式所需的灯光。
- 回读编辑窗口只读显示“导出时的数据体外观”。切换模式需要重新导出；宿主预览注明不模拟 Blender 灯光。
- 本次只改变 Blender 导出外观，不改变主程序体渲染、科学数据、颜色／透明度映射，不新增纯散射或等值面模式。

## 2. 接口、工程格式与兼容

以当前工作区为实施基线。已有大量未提交的显示质量和 Blender 改动，实施前检查差异，不覆盖或回退其他任务成果。

- 在[工程请求与契约](../../bandscope/exporting/blender_project.py)的 `BlenderProjectRequest` 增加 keyword-only 参数 `volume_mode="emission"`；未知模式在启动后台任务前报错。旧调用保持有效。
- 新建工程统一升级至 **schema 11**，同步场景与工程版本常量；独立显示的版本门槛仍为 schema 10，显示编辑格式仍为 2。
- 权威配置仍为资产目录中的 `scene.json`：
  - `project.volume_shading` 保存模式和解析后的材质参数。
  - 每个条目的 `volume_lighting` 保存灯组、接收者、灯对象及实际位置、尺寸、颜色和功率。
  - 新版将 `density` 描述为“总消光系数”；数组数值、VDB 网格与资产路径不变。
- schema 7–10 缺少模式时按现有自发光解释，原位更新不升级、不补新灯光；更早工程继续沿用已有兼容路径。
- 原位更新继续只替换 VDB、NPZ 和 JSON，**不保存或改写 `.blend`**。新增条目灯光字段加入更新保留名单，工程级模式与参数原样保留。
- 导出配置描述的是生成时设置，不声称反映用户随后在 Blender 中的修改。生成产物的严格默认参数校验不得用于拒绝用户手调过的工程更新。

## 3. 材质与灯光实现

在 [Blender 独立脚本](../../bandscope/exporting/blender_script.py)中按模式创建材质；配置通过现有任务 JSON 传入，不引入对宿主包的运行时依赖。兼顾工程导出和旧单场景调用。

### 材质

沿用现有 `Volume Coefficients`、对象空间密度、裁剪遮罩和线性 RGB 色带。令 `σ` 为裁剪后密度乘密度倍率，`c` 为现有颜色调整后的线性 RGB：

| 项目 | 自发光模式 | 柔和受光模式 |
|---|---|---|
| 散射反照率 `ω` | 0 | `0.65 × clamp(c, 0, 1)` |
| 散射系数 | 0 | `σ × ω` |
| 吸收系数 | `σ` | `σ × (1 − ω)` |
| 发射系数 | `σ × c` | `0.15 × σ × c` |
| 各向异性 | 0 | 0 |

- 混合模式逐 RGB 通道满足“吸收＋散射＝原总消光”，避免直接叠加散射使数据体额外变厚。
- 保留 `Density multiplier=1`、`Color adjustment`，新增清晰命名的 `Scattering amount=0.65`、`Emission compensation=0.15`、`Anisotropy=0` 参数节点。
- 散射比例限制为 0–1，发光补偿非负；零密度区域的吸收、散射和发射必须全部为零。
- 两种模式不共享可变材质实例；不同条目也保持材质独立。
- 第二模式采用至少 128 samples、`volume_bounces=2` 和现有去噪；采样数取现有薄板要求与 128 的较大值。保持现有色彩管理及透明背景，第一模式的渲染设置不变。

### 灯光

每个混合模式条目创建三个中性白色 Area 灯。以数据体中心为中心，使用导出相机的 right／up／backward 基向量确定初始方向，生成后固定在条目局部坐标，不绑定相机运动。

令 `L=max(数据体最大边长, 0.1)`、灯距 `d=2L`；下表方向先归一化，再乘以 `d`，全部灯朝向数据体中心、边长为 `L`：

| 灯 | 相机基向量中的方向 | 功率 |
|---|---|---|
| 主光 | `(-1, 1, 1.5)` | `60 × d²` W |
| 补光 | `(1, 0.3, 1)` | 主光的 25% |
| 轮廓光 | `(0.5, 1, -1)` | 主光的 50% |

- 灯组位于对应数据 Collection 内，灯父对象为该条目的 Root；专用 receiver collection 只包含该 Volume。
- 使用现有 [Cycles 灯光链接机制](https://docs.blender.org/manual/en/latest/render/lights/light_linking.html)限制直接照明；不宣称隔绝所有间接光。真实渲染必须验证 Volume 的接收效果。
- 灯不参与条目间距、总览相机和取景边界计算；Append 数据 Collection 后连同灯组和接收者一起保留。
- 保持薄板与文字的独立灯组。数据漫透射薄板可能因数据体发光减弱而变暗，说明这一表现，不通过偷偷增加发光补偿恢复旧外观。

上述数值作为首版明确默认值，尚未经过视觉验收。

## 4. 验证与验收

### 自动化回归

- 覆盖请求默认值、非法模式、UI 选择传递与忙碌禁用、新版元数据往返，以及旧 schema 7–10 回读／更新不升级。
- 相同快照在两模式下生成相同的强度、颜色、透明度和密度数组；模式不影响科学数据转换。
- 合成灰阶、RGB 和边界颜色验证系数非负、总消光守恒、零密度无底雾。
- 新导出保存重开后，验证实际材质节点连接、参数、独立灯组及接收者，并由宿主检查报告后提交产物。缺失或错连应阻止提交。
- 修正已有“零散射”验收：按模式检查实际连接和上游参数，不能只检查 socket 的 `default_value`，因为接线后默认值仍可能为零。
- 更新工程后，确认 `.blend` 摘要、模式、灯光元数据及用户修改的材质和灯光保持不变。
- 运行受影响模块回归、`python -m unittest discover -s tests -t . -v` 和 `git diff --check`。

### 真实 Blender 与视觉对照

- 合成灰白体和彩色体：同相机、同密度对比两模式；隔离环境照明后，混合模式关灯仍有弱颜色，开灯产生明显方向性明暗；移动灯不改变几何。
- 使用默认真实数据 `.local/data/WSe2_step.npz` 输出同视角两模式对照及弱带局部图，检查内部连续性、遮蔽、偏色、过曝，以及去噪是否抹掉细带；记录 128／256 samples 的图像与耗时。
- 覆盖多页独立灯光、全部辅助预设关闭、八种薄板与文字共存、目录搬移、Append、显示编辑后的原位更新。
- 真实窗口验证两个模式均可导出；补做开发冻结包的导出与重开冒烟，验证独立脚本链路。
- 自动化与实施者看图通过后，仍单独保留维护者人工视觉复核，不把“生成成功”写成“质感已获认可”。
