## 阶段 B：生命周期、安装事务与失败恢复

### 状态归属与重启行为

- 将下一次启动的期望配置与当前会话实例分开。磁盘记录插件期望版本、期望启用状态、待卸载请求与操作错误；当前加载版本、实例、运行错误和面板仅由会话持有。
- `ready_plugins()` 只依据当前运行实例及其运行状态。用户点击停用、启用或卸载时只改变期望配置，不能通过修改 `load_error` 或替换 record 立即改变当前效果。
- 覆盖安装只登记候选版本，不丢弃当前实例；退出由一个统一入口释放所有已创建实例，每个实例的 `release()` 恰好调用一次。创建面板或后续初始化失败时，也要释放已创建实例。
- 管理窗口同时显示当前状态与待生效操作，例如“运行中；待重启停用”“当前 1.0.0；待重启更新至 1.1.0”。新装未加载的插件显示“待重启加载”，不能显示“已启用”来暗示已经运行。
- 更新保留用户原有启用意愿；首次安装默认启用。重启前反复启停只保存最后一次选择，选择恢复到当前状态后移除对应待生效提示。
- 卸载请求立即阻止后续启动加载该插件，当前会话继续保留实例直至关闭。阶段 A 的待卸载按钮限制保留；重新导入同一个已校验包可在确认后撤销待卸载请求。

### 安装与登记表

- 在 extensions 内拆出独立存储与包安装服务，管理窗口只调用 `PluginManager`；所有读写使用同一个 `manager.root`。修复目前传入自定义 root 后部分操作仍读取环境变量根目录的问题。
- 登记表升到 schema v2：每条记录包含配置修订号、`desired`（包引用和 enabled）、`last_good`、`previous_good`、待卸载标记、来源验证信息与最近操作错误；运行实例不序列化。包引用含 id、version、相对路径、内容摘要；下载原包 SHA-256 单独保存。
- 版本内容按 `installed/<id>/<version>/<内容摘要>/` 不可变保存。内容摘要由受校验分发文件的规范相对路径、文件长度与文件字节按排序计算；禁止在运行中覆盖或删除已加载目录。插件字节码缓存和运行输出不写入内容目录，加载器不使用未纳入来源校验的包内字节码。
- 安装流程为“校验 → 临时目录解包 → 完整性检查 → 不可变目录落盘 → 原子替换登记表”。提交前失败保留旧登记表；目录已落盘但登记失败的内容视为未引用内容，下次安全启动清理。临时登记文件使用唯一名称。
- 同一 id/version 与相同内容重复安装保持幂等；同版本内容不同拒绝覆盖，要求发布方提升插件版本。历史包迁移保留自身内容摘要，不把同名历史包当作相同内容。
- schema v1 迁移先验证并备份登记表，核对安装路径在固定根内且 id、version、manifest 一致，再转换 enabled、路径及旧卸载标记；v2 原子提交成功后才清理旧标记。
- 登记表损坏、条目结构异常或未知 schema 时保留原文件并显示诊断，禁止以空表覆盖。无法确认的条目不加载；已能确认的其他条目可只读展示。

### 多实例、卸载与回退

- 根目录读改写使用跨进程文件锁；每个插件会话持有会话租约。锁封装采用标准库操作系统文件锁，Windows 与 CI 平台分别适配，避免为包校验和构建引入 Qt 依赖。租约释放由操作系统锁判断，不凭文件存在或时间戳猜测进程仍在运行。
- 创建/注销会话租约与存储事务由根锁协调；插件代码在锁外导入。只在启动加载前、没有其他活跃会话时执行卸载和旧目录清理；有其他实例时保留请求，提示关闭其他 BandScope 窗口后重启。
- 卸载实际删除失败时保留待卸载记录与错误原因，下一次安全启动重试；只有确认目标已移除才从列表清除。新会话不加载待卸载插件，不能用 `ignore_errors=True` 隐藏失败。
- 插件完成实例化及面板初始化后，宿主才将候选标记为 `last_good`，把不同的上一个成功版本保留为 `previous_good`；返回无面板的合法插件允许成功。健康回报携带启动时该插件的配置修订号与候选内容摘要，在根锁内确认仍对应当前 `desired` 且非待卸载后才能更新成功历史，避免旧实例晚回报覆盖新选择。保留当前版本、一个回退版本及待安装内容，其余仅在安全启动清理。
- 加载新版本失败时记录失败，不在同一进程自动导入旧代码。管理窗口提供“重试加载”和“恢复上一版本”，均登记后重启执行；失败候选不同于 `last_good` 时恢复 `last_good`，当前候选已经是 `last_good` 时才选择 `previous_good`，恢复前重新检查目标与当前宿主兼容。相同失败候选未经用户重试不得反复自动执行。
- 旧登记表备份用于迁移恢复；不承诺迁移后旧宿主可以直接写入 v2。降级主程序前需使用匹配的备份恢复流程，文档明确不能混用不理解 v2 的旧版实例。

### 诊断与验收

- 汇总导入、面板、上下文、倍率计算与状态恢复错误到管理窗口的插件详情。记录阶段、插件版本、错误摘要，技术栈写入本地日志；同一错误不在每次刷新重复弹窗。
- 插件返回值转换及尺寸检查纳入单插件异常边界；单个插件失败跳过其效果，其他插件继续运行。捕获 Python 异常不等同于进程沙箱，不能承诺隔离无限循环或原生崩溃。
- 测试覆盖：停用/卸载前后当前效果一致，重启后切换；运行中更新不丢实例或页面状态；失败实例释放；重复 shutdown 不重复释放；自定义 root 的全部操作一致。
- 故障注入覆盖：解包失败、磁盘不足、原子写失败、文件占用、删除失败、损坏登记表、非法路径、迁移中断、未引用目录恢复、回退不兼容。两进程测试验证无丢失更新且不删除另一实例正在使用的内容。

## 阶段 C：统一兼容规则

- `requires_app` 为裸版本时继续按精确版本匹配；带运算符时支持明确的版本范围，例如 `>=1.10.0,<1.11.0`。旧清单不自动放宽或重写。
- 使用 `packaging.version.Version` 与 `packaging.specifiers.SpecifierSet`，替换当前抽取数字的比较方式；安装、启动加载、构建脚本、目录筛选与升级评估共用一个纯函数。范围解析依据 [Packaging 官方文档](https://packaging.pypa.io/en/stable/specifiers.html)。
- `api_version` 仍为整数；宿主声明支持集合，初始为 `{1}`。判断应用范围、API 支持集合及所需能力都通过后才加载，不能只因主程序小版本接近就认定兼容。
- 新发布插件采用可排序版本；稳定目录默认只推荐稳定版本，不自动选择预发布版或降级。旧非标准插件版本仍可本地展示，但不参加在线“最新版本”比较。
- 兼容范围只覆盖已在回归矩阵验证的宿主版本。构建脚本检查当前宿主落在声明范围内；CI 明确记录所测宿主/API 组合，不能仅修改上限就声称兼容未来版本。
- 插件代码、资源、入口或兼容声明变化均提升插件版本。发布前检查同一 id/version 的内容不可变；现有平带插件从历史 1.0.0 转入新发布机制时必须提升自身版本，不能继续只跟改 `requires_app`。
- 增加直接依赖 `packaging`，同步插件构建 CI 的最小依赖与两套冻结构建。
- 验收：精确旧声明、范围内外、边界与排除版本、非法声明、预发布版本、未知 API/能力；构建、安装、启动和目录评估对同一输入返回相同结论及可读原因。

## 阶段 D：官方来源验证与发布约束

### 验证协议

- 官方信任依据为应用内置公钥验证通过，不依据 `author` 文本、文件名或普通 SHA-256 sidecar 判定。“官方已验证”“本地未验证”“历史未验证”分别展示。
- 使用 `cryptography` 的 Ed25519 签名接口，不自行实现密码算法。包与目录分别签名，使用不同用途前缀加原始文件字节作为签名输入；验证相同字节，避免重新序列化 JSON 引入差异。接口依据 [Cryptography 官方文档](https://cryptography.io/en/latest/hazmat/primitives/asymmetric/ed25519/)。
- 构建产物保留 `.bsplugin` 与 `.sha256`，新增 `.bsplugin.sig`；目录使用 `plugins-index.json` 与 `.sig`。签名 sidecar 明确协议版本、key_id、算法及 Base64 签名，宿主只接受已支持协议与内置可信 key_id。
- 在线安装先验目录，再校验下载包的签名、SHA-256、大小、id/version 与兼容声明。任何验证失败均不提交安装，不执行包内代码。
- 本地导入自动读取同目录签名；有签名但无效或未知密钥直接拒绝，不能自动降级为未签名包。无签名包需展示来源未验证提示，由用户确认后按包摘要记录本地信任，默认取消；包内容变化需要重新确认。
- 已安装旧包迁移为“历史未验证”，保留用户启用设置，不自动赋予官方身份。已验证官方插件不能被未签名包静默覆盖；更换来源须明确展示并确认。
- 验签、解包和提交使用同一份受控暂存文件；登记可信包摘要，重启激活前再次检查候选内容摘要，防止暂存内容被意外修改后直接执行。

### 密钥与 CI

- 私钥由维护者保存在发布环境的 Secret，仓库与安装包只包含公钥；密钥配置、轮换和恢复流程写入发布文档。新公钥通过宿主更新部署，旧公钥按明确的支持期保留，目录不能自行添加可信公钥。
- 正式官方发布要求签名密钥与内置公钥匹配，缺失时发布任务失败；本地开发构建可显式生成未签名测试包。当前未确认维护者密钥已配置，这属于发布验收前置项，不能标为已完成。
- 主程序依赖显式增加 `cryptography`；同步发布脚本、插件构建 CI 最小依赖和两套冻结包验证。包、签名、目录之间的版本、摘要和来源不一致时阻止发布。
- CI 保留基础包不得包含插件源码的检查；签名验证不是插件运行沙箱，现有插件仍是进程内 Python 代码。
- 验收：有效签名、篡改、缺签名、未知密钥、目录与包身份不一致、摘要不符、不同来源替换、旧包迁移；测试使用临时生成测试密钥，不依赖正式 Secret。

## 阶段 E：官方目录、插件更新与主程序升级衔接

### 官方目录与下载

- 管理窗口增加“已安装”和“官方插件”页签。已安装页集中安装、启停、卸载、恢复上一版本与错误详情；官方页提供刷新、说明、安装和检查插件更新。
- 每个正式 GitHub Release 增加经过签名的插件目录。目录记录 schema、递增目录修订号、生成时间、宿主版本与支持 API 集合，以及插件 id/name/version、应用范围、API/能力、包和签名的不可变 Release 地址、大小、SHA-256 与说明。
- 目录保留仍受支持宿主的历史匹配包，不能只列当前最新版主程序对应的包。聚合旧记录时验证来源，不把已存在的 id/version 改为不同内容；历史未签名包不自动列为官方已验证包。
- 打开官方页时后台获取目录，也可手动刷新或检查插件更新；不新增启动弹窗或自动下载安装。筛选最高的兼容稳定版本，显示不兼容原因。
- 在线安装或更新前展示来源、当前版本与目标版本，由用户确认。历史/本地插件按 ID 对应到官方包时，必须明确确认来源转换；不静默替换或自动降级。
- 从更新服务抽取可共用的 HTTPS 主机校验、超时、进度及取消机制；不要直接复用只接受 `.exe` 的安装器下载函数。请求与重定向都校验允许主机；目录最大 2 MiB、包下载最大 64 MiB，解包仍执行现有总大小和条目上限。
- 下载写入临时文件，取消或失败不改变登记表；验证通过后交给阶段 B 的统一事务。网络与下载在工作线程执行，界面更新回到 GUI 线程，关闭窗口可取消当前下载。
- 缓存最后一次验证通过的目录并显示更新时间；断网时可浏览缓存，但新下载必须有当前验证有效的元数据。目录验签失败时禁用本次在线安装，不能使用未验证内容；低于本机已接受修订号的目录拒绝替换缓存。

### 主程序升级前检查

- 使用签名目录中的目标宿主版本及支持 API 集合评估已安装插件，不能把当前 API 版本当作未来宿主接口。元数据缺失或离线无法确认时显示“兼容性无法确认”。
- 主程序更新提示增加插件影响清单：可继续使用、升级后暂停加载、存在匹配更新、无法确认。下载结束、启动安装器前重新评估，避免用户期间已改变插件状态。
- 存在不兼容或未知时默认选择“稍后”；用户可明确继续。升级保留插件文件和启用意愿，启动时不兼容插件暂停加载并显示原因。
- 第一版在升级提示中提供匹配包说明，升级完成后由用户在插件管理中确认更新；不提前把仅适用于未来宿主的包切换到当前运行环境。
- 对目标宿主的评估只读取清单，不导入插件代码。主程序更新失败或用户取消时，当前插件配置保持原样。

### 验收

- 多版本目录与旧宿主匹配、仅有不兼容包、无更新、来源转换、同版本不同内容冲突、预发布过滤与禁止自动降级。
- 断网、超时、限流、缓存、过期修订号、非法重定向、超限包、取消下载、损坏下载和签名失败；以上失败均不破坏当前安装。
- 主程序更新前后插件状态变化、用户取消、目标 API 未知、找不到匹配包，以及升级后保留配置但不加载不兼容插件。
- 正式签名密钥、签名目录发布、线上 Release 和冻结安装包验收分别记录状态；任何前置项未完成都不得宣称官方在线安装已经可用。

## 阶段 F：最小分析插件 API

### 首个能力范围

- 首次扩展限定为“当前已完成的 2D 数值结果 → 后台纯数值计算 → 新增 1D 结果页”，用合成数据积分演示插件验证。暂不扩成任意数据读取、任意 VTK 操作或通用文件导出框架。
- 保留 API v1 平带插件原接口和 3D 面板行为；新增 `PluginHostV2` 和 API 2 支持，宿主支持集合扩为 `{1, 2}`。v1 插件仍取得 v1 适配器，不能被迫实现新抽象方法。
- API 模块保持无 Qt/VTK 依赖；状态对象、数据轴说明、任务输入与数值结果采用普通数据类。能力声明增加 2D 数据快照、分析任务与 1D 结果提交，能力检查与面板显隐统一由宿主处理。

### 数据、任务与结果归属

- 提供只读 `AnalysisInput2D`：包含来源 page_id、数据代次/页面修订号、快照 ID、ROI 与帧信息、二维数值及对应坐标/单位。数组顺序统一为 `[x, y]`，坐标与对应维度等长并保留输入方向。仅允许抓取已完成的精确计算结果；预览、计算中、非 2D 或首版尚不支持的非矩形裁空状态返回明确不可用原因。
- 快照从宿主当前数值结果构建，不借用带排版、色阶或均匀网格限制的出图快照。数组复制到任务拥有的缓冲区并设为只读，不暴露可写原始数据；无单位元信息时保持未知或 index。
- v2 宿主提供 `capture_analysis_input()`、`submit_analysis()` 与 `cancel_analysis()`；提交返回任务句柄，纯数值工作函数接收快照、冻结参数与取消信号，返回 `AnalysisCurve1D`，包含 x/y、轴名/单位、标题和可序列化参数。结果页由宿主收到成功结果后统一注册，插件不直接创建页面或操作窗口。
- 当前 `RefreshCoordinator` 只有一个待执行槽，不能直接塞入插件任务覆盖渲染请求。新增宿主管理的分析任务执行器：一个工作线程、最多四个排队任务、每个插件最多一个未结束任务；重复提交或队列满时明确提示忙碌。取消为协作取消，未退出前不启动该插件的新任务；图形操作只在主线程完成。
- 任务绑定来源页面、数据代次和独立快照；切页或修改仍存在来源页的帧/ROI不把结果挂到新当前页，也不强制取消已提交快照计算。结果保存提交时的参数和坐标，挂在原来源页下，完成后不强制切页。
- 加载新数据、关闭来源页、用户取消或退出应用时发出取消请求，完成回调再次核对令牌与数据代次，失效结果丢弃。不能强制终止正在执行的 Python 线程或在窗口销毁后访问控件。
- 宿主校验结果为非空、等长的一维 x/y，x 必须有限，y 允许 NaN 表示缺测但拒绝无穷值；不把缺测伪造为零。按已有 `AnalysisPageSpec` 来源关系创建 `plugin_curve` 结果页，记录插件 ID/版本、参数、来源与快照修订号。数值缓冲区由宿主接管，插件停用后已生成结果仍可查看；展示及数据导出复用宿主已有 1D 路径。
- v2 分析面板按能力在 2D 页显示；保留 v1 平带面板仅在 3D 显示。每页参数由宿主保存，插件无需访问主窗口私有字段。

### 验收

- 演示插件使用小型合成二维数组，按指定轴积分，输出与 NumPy 参考计算逐项一致；原始强度逐位不变，坐标、单位、结果标题与来源正确。
- 验证运行中窗口可操作、队列上限、重复提交、取消、关闭源页、切页/帧/ROI时快照来源仍正确、新数据加载、无效返回值、后台异常及退出时回调处理；分析任务不能覆盖正常渲染任务。覆盖非均匀/降序坐标、缺测值、结果页改名/导出/关闭与数组释放。
- v1 平带插件无修改继续加载、显示和保存参数；v2 能力缺失时在导入代码前拒绝。新接口通过合成演示插件端到端验收后才文档化为正式支持能力。
