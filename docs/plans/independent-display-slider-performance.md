# NiHITP 大体数据色阶与独立透明度滑条优化

2026-11-20。三项应用优化已实施，真实窗口与自动化验收记录见文末。

## 目标与测量条件

缩短 3D 主页黑场、白场、灰场和四个独立透明度参数的拖动反馈时间，松手后按最终参数显示精确帧。已有的[局部增强交互性能计划](enhancement-render-performance.md)记录了 CUDA 映射、范围缓存和 ROI 异步处理，本次测量针对无局部增强区域的默认独立显示模式。

- 数据为 `D:\ARPES数据\npz_files\NiHITP\NiHITP_cornercut_3.npz`。静态 `float32` 体数据尺寸为 200 × 200 × 352，共 1,408 万体素，含裁空区域。
- 基线使用提交 `82916eb` 对应的显示代码，Core Ultra 5 245KF、RTX 5060 Ti、原生 Windows Qt 主窗口，VTK 画布为 1820 × 1036 像素。采用隔离设置、默认 0–99.5 百分位归一化，等待首次加载和统计完成。
- GPU 后端每个滑条测 3 次，共 21 帧。CPU 后端每个测 2 次，共 14 帧。单帧计时从预览派发到刷新返回，另用连续输入测定时器对实际出帧的影响。切换 CPU 后端改变的是通道计算，窗口继续使用 VTK 体渲染。

| 两个通道重排并写入 VTK 主存缓冲 | 约 92 ms | 约 93 ms |
| VTK 绘制调用 | 约 38 ms | 约 37 ms |
| 整次预览中位数 | **170 ms** | **1,161 ms** |

滑条信号处理约 0.4–1.1 ms。任一参数变化都会使整组显示缓存失效，GUI 线程随即为全卷重算两个通道。GPU 返回按通道分开的数组，VTK 需要按体素交错排列。每帧两次数组复制处理合计 107.4 MiB，占 NVIDIA 路径约 90 ms。热态采样中复用了归一化统计和已有体场景。[显示缓存](../../bandscope/app/enhancement_integration.py#L828) · [通道计算](../../bandscope/processing/display_transfer.py#L151) · [VTK 缓冲写入](../../bandscope/rendering/local_enhancement.py#L77)

连续约 2 秒模拟拖动时，灰场和整体密度分别在松手前显示了 7 帧和 6 帧预览。整体密度相邻预览的启动间隔约 340 ms。当前调度在上一帧结束后还会按上一帧耗时等待。慢帧下另有收尾顺序问题：同一轮请求将预览延时设为 250 ms、空闲精确帧保持 180 ms 时，Qt 实测先在 184 ms 派发精确帧，再于 246 ms 派发旧预览。[主窗口交互刷新](../../bandscope/app/refactored_app.py#L1438) · [刷新调度](../../bandscope/rendering/refresh_pipeline.py#L135)

## 实施顺序

1. **先改 GPU 输出布局。** 在 GPU 按 VTK 需要的体素顺序交错输出颜色与透明度，回传后连续复制一次。独立搬运实验使用该文件的尺寸和数据，预热后交替测量 9 轮，打包、回传与主存写入的合计中位数从 97.6 ms 降至 17.8 ms，最终缓冲逐位一致。优先接入此路径并复测整窗，记录实际单帧收益。[GPU 输出](../../bandscope/processing/gpu_display.py#L155)
2. **按滑条实际影响的通道更新。** 独立模式下，黑、白、灰场只重算颜色，阈值、起始过渡宽度、透明度 Gamma、整体密度只重算透明度。复用另一通道；换数据、归一化范围或区域归属时使相关通道失效。随后将 CPU 映射移到后台，拖动时只保留最新待算值，丢弃过期结果，VTK 提交留在主线程。[独立透明度公式](../../bandscope/processing/display_transfer.py#L134) · [主线程刷新入口](../../bandscope/app/refactored_app.py#L1659)
3. **修正连续预览和松手时序。** 按上一帧开始时间安排下一次预览，消费最新参数。七个滑条统一在释放时提交最终精确帧，并撤销同一轮尚未执行的预览。键盘和数值框保留空闲提交。现有黑、白、灰场已接入释放信号，四个独立透明度控件仍依赖空闲计时器。[色阶信号](../../bandscope/app/refactored_app.py#L2165) · [透明度控件](../../bandscope/ui/page_render_control.py#L264)

## 验收

- **真实窗口性能。** 在同一文件、视角、画布尺寸、显示参数和计算后端下，复测七个滑条。分别记录单帧耗时、连续拖动的实际出帧间隔、松手到最终画面的延迟。分段记录通道映射、缓冲写入与绘制时间，和上述基线对照。
- **图像与数值。** 自动化回归使用合成数据，逐体素比较优化前后的颜色和透明度。检查两通道独立性、极端灰场下的弱带、NaN 裁空边界、区域重叠和插件透明度倍率，保持映射与插值的先后顺序。[独立显示](../../tests/processing/test_independent_display.py#L45) · [弱带](../../tests/rendering/test_display_transfer.py#L113) · [插件倍率](../../tests/rendering/test_volume_quality.py#L85)
- **最终帧。** 覆盖快速拖动、松手、键盘和数值框输入，以及预览计时长于精确计时的情形。检查最后画面对应最新值和精确质量，迟到的预览或后台结果不能覆盖它。[调度回归入口](../../tests/rendering/test_refresh_pipeline.py#L25)

## 实施与真实窗口验收记录

2026-11-20 已完成三项实现：GPU 以 Fortran 体素序交错打包两个通道并一次回传；无局部增强区域的独立 3D 显示按颜色／透明度分别复用和计算，CPU 大体数据映射由单 worker 后台执行且只保留最新任务；预览间隔从上一帧开始时间计算，七个滑条释放时撤销待执行预览并提交最终精确帧。键盘和数值框仍保留空闲提交。最终精确帧是否可跳过由最后已完成帧的质量决定，避免预览后被误跳过，也避免已有精确帧的重复绘制。

真实窗口使用计划指定的 `NiHITP_cornercut_3.npz`、默认 0–99.5 百分位归一化和原生 Windows Qt/VTK。Qt 缩放为 1.25，实际截图均为 1755×1036 像素；与基线的 1820×1036 相比高度相同、宽度少 65 像素，因此以下不是严格同画布尺寸的复测。每个控件做两次单步预览／释放和一次约 2 秒连续输入，所有最终值均与控件一致且 `_render_exact_ready=True`。原始逐帧记录和最终截图在 `.local/outputs/independent-display-slider-performance/`。
