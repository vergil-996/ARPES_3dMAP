# 「相机视角」模块实现交接

日期：2026-09-26  
项目：ARPES_3dMAP  
目标：在现有桌面应用中实现可精确调整的 3D 相机面板，并让它随 3D 视图平滑出现、随其他视图平滑收起。

## 1. 用户要求与本次范围

用户原话：

> 像加载时间轴滑条一样丝滑，“相机视角”模块只在切换到3d视图时加载出来，另外按钮只需要一个“视角重置”按钮即可。
（实现时按钮文案最终定为「重置视角」。）

结合前面的讨论，实现以下内容：

- 放置位置：右侧「渲染控制」页面顶部，「色带选择」之前。
- 模块名称严格使用「相机视角」。
- 四个数值参数：方位角、仰角、滚转角、距离。
- 唯一的操作按钮：「重置视角」。
- 显示有效 3D 场景时平滑展开；切换到 2D、1D 或其他非 3D 页面时平滑收起。
- 鼠标操作相机后，输入框跟随真实相机状态；修改输入框后，更新相机画面。

本次不增加轴向预设按钮、保存/恢复视角按钮、应用按钮、右键菜单入口或手动折叠开关。模块的展开和收起由当前视图决定。

本文件是需求交接文档（正文为待实现的要求）。实现已于 2026-09-26 完成，
落地情况见文末「8. 实现结果」。

## 2. 布局与控件

建议布局：

```text
相机视角
  方位角 [ 45.0° ]    仰角 [ 30.0° ]
  滚转角 [  0.0° ]    距离 [  …   ]
             [重置视角]

色带选择
  ……现有内容……
```

- 复用现有分组卡片、标签、数值框和按钮的主题样式与宽度规则。
- 输入框支持直接输入和上下微调。三个角度显示一位小数，默认微调步长建议为 1°。
- 距离表示相机位置到观察中心的距离，使用渲染坐标单位；不要标成物理长度，也不要改成没有说明的缩放百分比。精度和步长应适应实际场景尺度。
- 输入须为有限数值，距离必须大于零；角度范围及规范化规则须与实际采用的相机姿态定义一致。
- 键入数值在 Enter 或失焦时提交；微调按钮立即生效，避免用户尚未输入完整数字就反复转动画面。
- 窄窗口下保证标签和数值完整可读，必要时改为一行一个参数。

## 3. 显隐条件与动画

### 3.1 判断当前实际视图

以本次渲染得到的有效上下文及实际显示的画布为依据。正常路径中应要求 `context["view"] == "3d"` 且正在显示 3D 场景。

不要只判断原始数据维度、页面名称或 `left_display_stack` 的索引：当前代码在未加载数据时也会显示索引 0 的 3D 容器，部分结果页则可能显示不同维度的内容。

需要覆盖：

- 有效 3D 主页、时间积分 3D、其他实际显示 3D 的结果页：显示。
- 2D 切片、1D 曲线、比较页、控制页面、无数据和空结果：隐藏。
- 渲染失败、提前返回等路径：按最后实际保留的有效画面处理，不能残留与画面不匹配的面板。
- 右侧当前处于其他控制标签页时，也要更新目标显隐状态；切回「渲染控制」后状态正确。

### 3.2 复用时间轴的过渡方式

已确认项目已有公共显隐动画：

- `control_layout_utils.py`：`animate_widget_visibility()`。
- 默认时长 220 ms，高度收放与透明度变化同步，缓动为 `InOutCubic`。
- `set_widget_visibility_instant()` 用于启动等无需过渡的状态。
- `timeline_bar.py` 的 `TimelineBar.set_timeline_visible()` 使用目标状态缓存，避免重复播放。

优先复用这套机制，实现与时间轴加载一致的视觉感受：

1. 启动时直接隐藏，不能先闪现再收起。
2. 进入有效 3D 视图时，先同步真实参数，再展开并淡入。
3. 离开 3D 视图时，收起并淡出；结束后不留下空白占位。
4. 相同目标状态不重复启动动画，时间轴刷新和普通 3D 重绘不能让面板反复出现。
5. 动画中快速切换 3D/2D，应从当前视觉状态继续，最终状态与最新视图一致。
6. 下方色带等卡片随高度变化自然移动；动画过程中及结束后，滚动区域高度和位置正确。

「加载出来」首先指用户看到的按需出现效果。可以复用同一控件实例并切换显隐，无需每次销毁重建。若采用首次进入 3D 才创建的方式，也必须避免首帧卡顿和重复绑定信号。

## 4. 相机参数与双向同步

### 4.1 明确参数定义

方位角、仰角和滚转角必须采用同一套明确的坐标和旋转约定。实现时在代码注释中说明零点、正方向、取值范围，以及角度跨界和极点的处理。

以真实相机的 `position`、`focal_point`、`view_up` 为依据建立可往返转换的姿态表示。不要将用于增量旋转的接口或仅记录上次设置值的属性，直接当成任意鼠标操作后的绝对角度读数；先核查当前依赖实现，再决定转换方式。

基本行为：

- 改角度：保留当前观察中心和相机距离，只改变相机姿态。
- 改距离：保留观察中心和姿态，只沿视线方向调整距离。
- 滚转：绕视线方向旋转画面，不改变相机距离。
- 鼠标平移后的观察中心必须保留；修改角度不能突然跳回数据中心。
- 相机设置后按需更新裁剪范围，防止近远裁剪面导致场景消失。
- 输入框的显示舍入不能反写损失原始相机精度。

### 4.2 同步与性能

- 拖动旋转、Ctrl 滚转、滚轮缩放、平移、程序恢复相机、E 轴翻转及重置后，都要同步数值。
- 交互过程中可将数值同步合并至约 30 Hz；交互结束必须再同步一次准确结果。
- 编辑中的输入框不要被异步回读覆盖尚未提交的文本，提交或取消后再恢复同步。
- 使用 `QSignalBlocker` 或等效保护，避免「相机变化 → 输入变化 → 再次修改相机」循环。
- 修改相机仅执行必要的相机更新和画布渲染，不触发数据计算、去噪、体数据重建或完整 `global_refresh()`。
- 仅动画面板及其布局，不能给 VTK 画布添加透明度效果。
- 观察器和信号只绑定一次；窗口关闭时清理新增的观察器、计时器和待执行回调。

## 5. 「重置视角」的建议语义

用户已确定按钮文案和数量；本节给出便于直接实施的默认行为。

点击后，将当前有效 3D 场景恢复为统一的默认观察方向、默认滚转，并将观察中心重新对准当前展示内容，自动调整距离以完整显示场景。

- 默认观察方向应沿用应用初次展示 3D 数据时的约定，先检查现有初始化行为再实现。
- 按钮应真正恢复方向、观察中心和距离，不能只适配取景范围。
- 保留当前 E 轴翻转和 Z 轴数据旋转等控制状态；重置后的姿态应与现有 E 翻转机制一致，避免下一次刷新又旋转 180°。
- 不修改数据、裁剪范围、时间帧、色带、色阶或去噪参数。
- 重置完成后，同步输入框与现有相机快照。下一次 3D 刷新不能恢复到重置前的相机。

本次沿用现有相机记忆策略，不另行扩展按页面保存、持久化到磁盘或用户自定义预设。往返切换 3D/2D 时应保留现有的相机恢复行为。

### 角度约定

世界向上轴取 **+Z（数据体 E 轴，也是 VTK 的默认竖直轴）**，与 `render_core`
把体数据缩放成 0~200 立方体的方式一致：

- **仰角** `asin(offset·Ẑ / d)`，`[-90°, 90°]`；0° = 相机在 Kx-Ky 平面内平视，
  +90° = 从 +E 方向俯视（极点）。
- **方位角** `atan2(offset·Ŷ, offset·Ẋ)`，`(-180°, 180°]`；0° = 相机在 +Kx 一侧，
  +90° = 绕 +Z 逆时针转到 +Ky 一侧。
- **滚转角** 绕视线 `d̂ = -offset/d` 的右手旋转，`(-180°, 180°]`；0° = 画面向上
  对齐 +Z 轴在像平面内的投影。
- 极点处 +Z 的投影退化，0° 参考改取 `e → ±90°` 的极限方向，读写两端共用同一
  公式，因此极点附近往返仍然精确（极点本身的方位角在数学上不可定义，读数会
  退化为噪声，但画面与姿态往返不受影响）。
- 读、写都由向量公式导出，不使用 `vtkCamera.Azimuth()/Elevation()/Roll()` 这类
  增量接口；输入框的显示舍入（角度 1 位、距离 2 位）不反写相机——提交单项时
  只有该项取输入框的值，其余沿用相机精确读数。

### 重置的最终语义

默认观察方向 = **应用初次展示 3D 数据时的等轴视图**：`pyvistaqt.QtInteractor`
构造阶段调用 `Renderer.view_isometric()`，方向取自主题默认
`camera['position'] = (1, 1, 1)`、`viewup = (0, 0, 1)`，即方位角 45°、
仰角 `asin(1/√3) ≈ 35.264°`、滚转 0°（`DEFAULT_*` 常量有对应测试核对）。

点击「重置视角」时：把相机设成该方向 → `plotter.reset_camera()` 让 VTK 按当前
展示内容重新对焦并取景 → 把 `_camera_e_flip_applied` 置回 `False` 后交给既有
`_apply_pending_e_flip_camera()`，因此 E 轴翻转打开时得到「默认姿态 + 翻转」，
重复重置或后续刷新都不会再叠加第二个 180°。不触碰数据、裁剪范围、时间帧、
色带、色阶、去噪参数与 Z 轴旋转。

### 滚动（后续修复）

新卡片把内容顶高后暴露出一个既有缺陷：`SiScrollArea` 只在自身 `resizeEvent`
里更新滚动条，而控制页是靠 `container.adjustSize()` 改变内容高度的，滚动区域
自身尺寸不变 —— 内容高出视口后滚动条仍然隐藏，`wheelEvent` 里的
`scroll_bar_vertical.isVisible()` 判断又把滚轮一起挡掉，底部卡片既滚不到也
拖不到（时间轴卡片展开时同样存在）。

修复：`control_layout_utils.refresh_scroll_bars()` 用一次同尺寸 resize 事件复用
SiScrollArea 自己的那段计算，由 `ControlPageBase` 在内容尺寸变化后调用。另外
「相机视角」的数值框改为**只有已获得焦点时**才用滚轮微调，否则把滚轮让给页面
（滑条沿用 SiUI 原有的滚轮微调）。
