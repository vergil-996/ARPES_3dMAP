# BandScope v1.23.2

本版修正大数据连续拖动旋转旋钮时中间预览可能一帧都不出、只能看到松手后最终结果的问题：同一次旋转中，已经计算完成且未被更新输入超越的预览会实际呈现；更新的已呈现帧、其他交互或精确刷新派发仍会丢弃旧预览。

## 主要变更

- **连续拖动中间帧交付**：刷新协调器记录每页最新的交互原因、已呈现代次与精确派发代次。同一次旋转中，最近完成且尚未被超越的预览可以晚于更新的拖动输入交付，并按该请求自己的旋转角度构建画面，交付后恢复旋钮的最新输入角度；`axis_integral`／`axis_integral_crop` 的数组、法向区间与坐标语义不变。
- **旧预览阻断与缓存命中**：更新的已呈现帧、其他交互、页面取消或精确刷新派发都会让旧预览失效；不经过工作队列的缓存命中帧也计入已呈现代次，避免随后重绘同一帧。精确结果完成前，对确认裁剪／裁空和需要精确来源的局部增强的保护保持不变。

验证（Windows、仓库 `.venv`）：

- 全量 `python -m unittest discover -s tests -t .`：**2406 项通过**（2026-11-27，217.587 秒，单进程，日志 `.local/logs/release-1.23.2-full.log`）；`compileall` 与 `git diff --check` 通过。
- 定向回归：13 个旋转相关模块 **201 项通过**（2026-11-27，98.408 秒，日志 `.local/logs/live-rotation-directed.log`）。新增受控慢计算测试在修复前稳定得到空预览帧列表，修复后确认松手前两个角度均实际重绘画布，且最后呈现的是精确帧。
- 真实窗口（`.local/data/WSe2_step.npz`）：连续拖动专项在原生旋钮鼠标事件与计算结果交付门闩下确认鼠标仍按住时依次呈现 10°、20° 两帧预览，画布像素 SHA-256 不同，松手后呈现 20° 精确帧；报告与三张截图在 `.local/outputs/live-rotation-continuous/`。该结果属于自动操作与像素检查，不记为维护者真实鼠标流畅度人工验收。
- 未通过（沿用上一版已知缺口）：`verify_canvas_axis_slices.py` 在 WSe₂ 上 4/7 通过——`axis_integral` 创建精确值与 −15° 中间预览相对独立参考（`float64` 直接求和）最大绝对差 1.4e-3／1.8e-3（数据量级约 10³，超出脚本 `rtol=3e-5/atol=3e-5`），45° 最终精确帧等待 90 s 超时；报告在 `.local/outputs/live-rotation-continuous/report.json`。这两项不是本版连续交付修复的通过项，检查项与下一步见 [2D 切片实时旋转与空间交互工具共存](../../plans/live-slice-rotation-interactions.md)。

未执行：维护者人工视觉复核、真实鼠标流畅度、科研出图质量认可、冻结安装包与安装器的人工安装验收（以 CI 产物为准）。
